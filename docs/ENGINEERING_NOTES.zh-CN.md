# 云端陪伴助手模板工程说明

## 本次提取边界

这是重新编写的通用骨架，不是私人项目的整库复制，也不是已完成的 Hermes 产品。只保留有复用价值的设计边界：Telegram 可信接入、身份与群组隔离、持久化接口、重试语义及部署验收清单。个人角色、课程、知识档案、历史聊天、实际云项目、真实身份与运行凭据均不属于模板。

## 已实现与未实现

已实现：长 webhook secret 的恒定时长摘要比较、Telegram 数字 ID 校验、私聊发送人与聊天 ID 一致性、指定群与指定成员联合授权、租户/聊天/话题会话键、原子首次写入、入队失败返回 503、重复事件使用同一任务标识、Firestore 注入式适配器、GCS 指定 generation 和 SHA-256 校验、只创建不覆盖的快照写入，以及合成数据单元测试。

未实现：真实 Telegram HTTP 服务接线、Cloud Tasks、真实模型调用和真实发信、Hermes SQLite/Markdown 恢复、归档清理与生产监控。通用工作器、会话租约与 fencing、检查点和发信状态机已经实现并做合成测试，见后文恢复核心。默认服务仅用于容器健康检查，业务请求返回 503。这样可以避免“容器启动成功”被误认为“助手已经上线”。

## 为什么不直接嫁接 Hermes

传统文本模型端口只处理输入输出；Hermes 还涉及工具、副作用、会话文件、自然记忆和后台复查。直接替换一个文本调用会遗漏生命周期、隔离和恢复责任。因此先规定 turnId、可信 principal、会话键、截止时间、取消信号和耐久检查点，再单独验收实际桥接。现在的适配器明确抛出未实现错误，不用 mock 冒充集成成功。

## 关键取舍

1. 标准库优先：本地测试不需要安装额外包或接触账户，便于公开审核。云 SDK 由实际使用者固定版本后注入；当前 fake 测试不替代 emulator 或真实云测试。
2. 安全失败：授权失败不会读取私有资料；存储/入队异常不会返回接收成功；重复 ID 内容变化不会覆盖已存在记录。
3. 先持久化后入队：避免任务只在内存里存在，但仍需后续补齐事务 outbox 和 reconciliation，不能依靠 webhook 有限重试承诺最终交付。
4. 群内共享与私聊隔离：群成员可以共享同群同话题对话，但不继承某个成员私聊记忆。哈希键仅是命名方式，不是匿名化或权限系统。
5. 快照不等于运行盘：SQLite 必须一致性备份；不能把活动数据库放进 GCS FUSE。上传完成还需记录可信 generation 和一致性清单，再更新恢复指针。
6. 分层证据：单元测试、模拟 SDK、emulator、真实云环境和用户体验分别验收；未测项目明确标记，避免扩大结论。

## 发布前后

发布前需确定开源许可、再次脱敏审查、保留未来引入上游的版权与许可，并跑完整测试。当前目录没有上游代码，也没有私有仓库历史；原始代码已采用 MIT 许可，见 LICENSE。

上线前需独立测试机器人、最小 IAM、Secret Manager、队列身份验证、可恢复状态机、跨租户隔离、重启恢复、真正消息送达与回滚演练。90 天热数据、按月归档等都属于未来可配置政策，本模板没有自动启用任何生命周期或永久删除操作。

## 可运行的本地合成链路

npm run demo 提供仅监听 127.0.0.1 的演示服务，完整走入站、内存队列、工作器、合成提供方和本地回复数组。它不使用真实模型、不发送 Telegram、不读任何账户，重启丢失全部状态。另有撤销权限、重复排队、并发 drain 和提供方失败重试测试。通用工作器已经实现；生产队列、提供方、发信及云持久化接线仍未完成。

## 后续补齐：实际可复用的恢复核心

新增 SessionLedger 原子事务端口、Firestore 会话适配器和真正的工作器状态机。通过 owner、epoch 与过期时间逐次 fencing，维护 PENDING/RUNNING/PREPARED/SENDING/SENT 等状态。回复与 Markdown 记忆在 PREPARED 前一起落入事务；这个阶段之后恢复不重复调用模型。RUNNING 或 SENDING 中断会进入 QUARANTINED，避免把远端未知结果当成未执行；隔离记录阻止同会话后续消息越过它。

新增 FileSnapshots 使用 Node 原生文件系统完成临时文件、fsync、rename、目录 fsync 和 SHA-256 校验，并在独立 Node 新进程中恢复真实磁盘快照，验证 Markdown 记忆与终态去重都还在。这是单写者本地持久化，不是 Cloud Run 持久化，更不是已经实现 Hermes SQLite 原生桥接。恢复前必须停掉旧工作器，避免清除租约造成并行运行。

故障测试覆盖多个提交前后崩溃点、租约争抢、过期旧工作器、超时、授权撤销、未知发送与终态重放。异常模拟不等同于真实 kill 测试，Firestore fake 不等同于 emulator；详见 RECOVERY.md。真实生产接线仍未完成。
